프로젝트 제안: 코드 실행 과정 시각화 도구 (가칭)

한 줄 요약. 알고리즘 코드를 한 단계씩 실행하면서, 지금 실행 중인 줄과 그 줄이 자료구조의 상태를 어떻게 바꾸는지를 한 화면에서 함께 보여주는 웹사이트를 만든다.

1. 문제 정의

알고리즘을 배울 때 학습자가 만나는 것은 정적인 텍스트, 즉 소스 코드다. 그러나 알고리즘의 본질은 시간에 따라 변하는 상태에 있다. BFS의 큐에 무엇이 들어 있는지, 어떤 노드를 방문했는지는 코드 어디에도 적혀 있지 않고, 학습자가 머릿속에서 직접 시뮬레이션해야 한다.

이 시뮬레이션이 틀리는 순간 알고리즘에 대한 이해도 함께 틀어진다. 따라서 코드(정적)와 실행(동적) 사이의 간극을 눈에 보이게 메우는 도구가 필요하다.

2. 핵심 아이디어

사용자는 두 가지를 고르고, 버튼으로 실행을 한 단계씩 진행한다.

  1. 언어 선택: 같은 알고리즘을 여러 언어로 비교해서 볼 수 있다.
  2. 알고리즘 선택: 예를 들어 BFS를 고르면 해당 언어의 예시 코드가 나타난다.
  3. 단계 실행: 버튼을 누를 때마다 (a) 코드에서 현재 실행 중인 줄이 강조되고, (b) 그 줄이 만든 상태 변화가 시각화 영역에 반영된다.

핵심은 방금 실행한 연산이 코드의 어느 줄에 해당하는지와, 그 연산이 만든 화면의 상태 변화를 같은 시점으로 묶어 보여주는 것이다. 한 연산이 여러 줄에 걸치거나 언어마다 줄 수가 다를 수 있고, 조건 검사처럼 상태가 바뀌지 않는 연산도 있으므로 줄과 상태 변화가 항상 1:1로 대응하는 것은 아니다. 두 정보가 항상 같은 시점을 가리켜야 학습자가 인과관계를 추적할 수 있다.

5. 동작 예시: BFS

Python을 선택하고 BFS를 실행한다고 하자. 그래프는 A: [B, C], B: [D], C: [D], D: []이고 시작 노드는 A다. 아래는 화면에 나타날 코드의 모습이며, 노란색 줄은 "방금 실행한 연산의 줄"이며, 상태는 해당 연산을 실행한 뒤의 결과다. 준비된 예제의 실행 기록을 재생하며 사용자 코드를 실제로 실행하는 기능은 아니다. 

from collections import deque
def bfs(graph, start):
    visited = {start}
    queue = deque([start])
    while queue:
        node = queue.popleft()
        for nxt in graph[node]:
            if nxt not in visited:
                visited.add(nxt)
                queue.append(nxt)

버튼을 누를 때마다 다음 표의 한 행이 화면에 반영된다.

버튼을 누를 때마다 일어나는 일 (앞부분)
단계 실행 줄 visited queue
0 실행 전 {} []
1 3 {A} []
2 4 {A} [A]
3 5, 6 {A} [] (node = A)
4 7, 8 {A} [] (nxt = B, 아직 미발견)
5 9 {A, B} [] (nxt = B)
6 10 {A, B} [B] (nxt = B)

시각화 영역에서는 같은 정보를 그래프와 큐 그림으로 보여준다. 방문한 노드는 색을 바꾸고, 큐는 막대 형태로 원소가 들어가고 나오는 모습을 보인다.

6. 구현 접근 (초안)

핵심 설계 결정은 "실행 과정을 어디서 얻는가"이다.

  • 1단계 (미리 기록한 실행 기록). 알고리즘마다 (실행 줄, 상태) 쌍의 열, 즉 trace를 미리 만들어 두고 버튼이 이 열을 앞뒤로 넘기게 한다. 구현이 단순하고 언어별 차이는 코드 텍스트와 줄 번호 대응표로만 흡수할 수 있다.
  • 2단계 (실제 실행). 사용자가 입력한 코드를 브라우저 안에서 직접 실행하며 trace를 생성한다. 범위가 훨씬 넓어지므로 1단계로 사용성을 검증한 뒤 판단한다.

기능 관점에서는 다음 버튼과 함께 이전 버튼과 처음으로 버튼을 두는 것을 목표로 한다. trace가 배열로 저장되어 있으면 되돌아가기는 인덱스를 하나 줄이는 것만으로 구현된다.

7. 성공 기준

  • 학습자가 어떤 단계에서든 "이 줄이 실행된 결과로 상태가 이렇게 바뀌었다"를 화면만 보고 설명할 수 있다.
  • 새 알고리즘을 추가할 때 코드, trace, 시각화 규칙만 추가하면 되고 나머지 화면은 수정하지 않아도 된다.
  • 모바일 화면에서도 코드와 시각화 영역이 함께 보인다.

8. 범위에서 제외하는 것

  • 대규모 입력에 대한 성능 측정. 이 도구의 목적은 이해이지 벤치마크가 아니다.
  • 코드 편집기 수준의 기능 (자동 완성, 디버거 연동 등).
  • 진도 저장 같은 계정 연동 학습 기능. 회원가입·로그인·게시판은 수업 필수 항목이므로 범위에 포함한다.

9. 확정한 구현 정책

언어 표시 순서는 Python → C++ → Java → Kotlin → Rust → C → JavaScript입니다. 일곱 언어 모두 코드를 지원합니다.

  • 단일 언어를 전환하며 현재 의미 단계는 유지한다. Python의 deque 등 언어별 구현 차이는 한국어로 설명한다.
  • MVP에서는 검증한 고정 예제만 선택한다. 사용자 입력 편집은 후속 범위다.
  • 단계는 의미 있는 연산으로 나누며, 조건 검사·발견 기록·큐 삽입을 분리한다. 연산마다 언어별 코드 줄 목록을 대응시킨다.
